# POSE v6.2.0

## Added

- Add explicit, reviewable verdicts for stable POSE usage findings. `pose usage` and MCP `pose_usage` report adjudicated counts, false-positive rate and unmatched verdicts beside automatic observations. (pose-usage-findings-adjudication)

## Changed

- Structural assessment reuses one bounded Git batch reader for blob reads within an assessment, reducing process creation while retaining path, symlink and byte limits. The process is closed and reaped at the end of the operation. (pose-design-delta-batched-git-reads)
- Doctor identifies conflicting adoption dates, counts legacy sealed bundles and names invalid declarations inside stale review profiles. Roadmap checks explain when no cut criteria exist. Review verification retains selected sealed-evidence observation warnings, including for completed scopes whose approval is retained. (pose-governance-residual-diagnostics)
- Native Homebrew and WinGet verification is deferred to an explicitly dispatched GitHub Actions round after implementation. It no longer starts automatically after releases or blocks other implementation work; actual channel support claims still require successful native evidence. (pose-package-channels-deferred-native-verification)

## Fixed

- History checks in quiet mode emit one final verdict when unstaged or untracked JSONL is tolerated, preserving strict failure and tolerant success exit codes. (pose-history-quiet-tolerated-verdict)
- Release asset parity discovers nested documentation instead of relying on a manual source list. SBOM fixtures share the verifier's direct dependency parser. Local verification includes the current CI gates and explicitly identifies fast mode omissions. (pose-release-doc-discovery-and-sbom-parser)
- Delivery graph failures are reported once with their originating spec instead of being repeated against unrelated completed specs. Human authority issuer pins receive format diagnostics, authority claims use their envelope schema, and excluded lifecycle paths remain portable between checkouts. (pose-v6-2-0-delivery-authority-diagnostics)
- Contributor-mode manuals agree that agents request confirmation before staging local feedback and again before submitting it upstream. Review bundles can seal a root `.env.example` with its content intact. Package-channel checks inspect the installed binary in a fresh project instead of the source checkout. (pose-v6-2-0-release-stability)
