Git state that cannot be read is now unknown instead of clean. `pose close` blocks on a
working tree whose `git status` fails rather than sealing evidence over it, and the governed
snapshot, the review-bundle working-tree check and the obligation snapshot report an
unreadable status as unknown. A directory that is not a repository at all keeps its
behaviour.

`pose review dispatch` now compares the review worktree with the sealed commit's own tree,
before handing it to the reviewer and after the run, so a path hidden with
`assume-unchanged` or `skip-worktree`, a replaced type or a link can no longer pass as an
untouched tree. What a review tool may regenerate is a list of what each producer writes
(assessments, state, the derived indexes, new result, bundle and run records), no longer a
prefix: the validation matrix, the policy and existing sealed records are not regenerated by
a review. A run that finishes after its bundle was superseded, changed or its policy
changed is recorded `stale`: kept as history, not as the current fulfilment of the scope.

Stricter and classified minor: a dispatch that used to pass over a hidden edit, or over a
change to the validation matrix under `.pose/indexes/`, now fails.
