# POSE v0.16.0

## Added

- POSE now reconciles structured spec artifact claims against immutable Git change sets, persists report evidence and a reverse delivery-integrity index, and exposes strict CLI and read-only MCP checks with safe staged backfill. (pose-artifact-provenance-ledger)
- Adds the capability assessment as a POSE-native mechanism: a structured, versioned artifact at `.pose/capabilities/assessment.md` (flat frontmatter + per-mechanism flat bullets) with typed, mechanically verified evidence references; an append-only `history.jsonl` snapshot log; and the `pose assess` command family (`init` scaffolds the 16 default mechanisms, bare `assess` validates structure/evidence/stable-ids/staleness, `snapshot` appends, `diff` compares). `pose check --strict` runs the same validation when the artifact exists (opt-in by presence). The repository's own assessment (2026-07-19) is migrated as dogfooding. Second increment: MCP projections `pose_capability_state` and `pose_capability_history` (paginated, project-scoped, golden-catalog gated — 32 tools) and `pose assess diff --against <project-id>` comparing score matrices across roots through the portfolio-projection authorization allowlist. (pose-capability-mechanism)
- POSE now proves typed product surfaces and composed capabilities through Git-observed artifacts, production entrypoints and current profile-driven validation evidence, with strict roadmap cut criteria and matching CLI/MCP projections. (pose-delivery-surface-assurance)
- POSE now requires current, digest-bound reviews before closing specs, milestones or roadmaps and exposes a governed continuous-closeout terminal state so agents can remediate and re-review without prompt-only guarantees. (pose-hierarchical-review-closeout)
- POSE now consumes pending fragments into immutable version snapshots and tracks prepared, tagged, published and independently verified releases through provider-neutral evidence, safe automation and matching CLI/MCP status. (pose-release-lifecycle-closure)
